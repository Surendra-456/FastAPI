FASTAPI ROUTER ORGANIZING - COMPLETE GUIDE

OVERVIEW
--------
As FastAPI applications grow, keeping all endpoints inside a single main.py file becomes difficult. Router organization improves maintainability, scalability, testing, and team collaboration.

Benefits:
- Better maintainability
- Easier collaboration
- Reduced merge conflicts
- Better modularity
- Easier testing
- Scalable architecture

==================================================
1. WHAT IS APIRouter?
==================================================

APIRouter is a FastAPI component used to group related endpoints together.

Import:
from fastapi import APIRouter

Create Router:
router = APIRouter()

Purpose:
- Organize endpoints by feature.
- Avoid placing all routes in main.py.

==================================================
2. PROBLEM WITHOUT ROUTERS
==================================================

All endpoints are placed in a single file.

Problems:
- Huge files
- Hard navigation
- Merge conflicts
- Difficult debugging
- Poor modularity
- Difficult testing

==================================================
3. BASIC ROUTER SETUP
==================================================

routers/users.py

from fastapi import APIRouter

router = APIRouter()

@router.get('/')
async def get_users():
    return {'users': []}

@router.post('/')
async def create_user():
    return {'message': 'User created'}

main.py

from fastapi import FastAPI
from routers.users import router as users_router

app = FastAPI()

app.include_router(
    users_router,
    prefix='/users',
    tags=['Users']
)

Endpoints:
GET  /users
POST /users

==================================================
4. include_router EXPLAINED
==================================================

app.include_router(router, prefix='/users', tags=['Users'])

router:
- Router object being registered.

prefix:
- Adds a common URL prefix.

Example:
/users
/users/1
/users/create

tags:
- Groups endpoints in Swagger documentation.

5. RECOMMENDED FOLDER STRUCTURE
==================================================

app/
├── main.py
├── routers/
├── services/
├── schemas/
├── models/

Responsibilities:

routers/
- HTTP request handling
- Endpoint declarations

services/
- Business logic
- Validation rules

schemas/
- Pydantic request/response models

models/

database/

- Sessions and connections

Rule:
Routers should contain little or no business logic.

==================================================
8. ROUTER + SERVICE LAYER
==================================================

Bad Practice:
- Database access inside router.
- Business logic inside router.

Recommended Flow:
Router -> Service -> Response

Router:
- Handles HTTP requests.

Service:
- Contains business rules.
- Validation.
- Error handling.

Benefits:
- Thin routers.
- Reusable logic.
- Easier testing.

==================================================
9. REPOSITORY PATTERN
==================================================

Repository handles database communication.

Flow:
Router
 ↓
Service
 ↓
Repository
 ↓
Database

Benefits:
- Better separation of concerns.
- Simplified testing.
- Cleaner architecture.

==================================================
10. DEPENDENCY INJECTION
==================================================

Import:

Example:
router = APIRouter(
    prefix='/users',
    tags=['Users'],
    dependencies=[Depends(authenticate)]
)

Uses:
- Authentication
- Authorization
- Shared validations
- Common dependencies

Benefit:
- Avoid code duplication.

==================================================
19. COMMON MISTAKES
==================================================

1. Business Logic In Router
❌ Router contains business rules.
✅ Move logic to Service.

2. Huge Router File
❌ Single file with thousands of lines.
✅ Split by feature.

3. Direct Database Access
❌ Router -> Database
✅ Router -> Service -> Repository -> Database

4. No API Versioning
❌ /users
✅ /api/v1/users

FINAL REVISION POINTS
---------------------
1. Keep routers thin.
2. Put business logic in services.
3. Use repositories for database access.
4. Organize code by feature/domain.
5. Use dependency injection.
6. Version APIs from the beginning.
7. Separate auth and admin routes.
8. Use aggregator routers.
9. Follow enterprise architecture for large projects.
10. Maintain clear separation of concerns.

SQLite ORM Example Using SQLAlchemy

Install:

pip install sqlalchemy

Code:

from sqlalchemy import create_engine, Column, Integer, String
from sqlalchemy.orm import declarative_base, sessionmaker

Base = declarative_base()

class User(Base):
    __tablename__ = "users"

    id = Column(Integer, primary_key=True)
    name = Column(String, nullable=False)
    email = Column(String, unique=True)

engine = create_engine("sqlite:///app.db")
Base.metadata.create_all(engine)

Session = sessionmaker(bind=engine)
session = Session()

# Insert
user = User(name="Surendra", email="surendra@example.com")
session.add(user)
session.commit()

# Query
users = session.query(User).all()
for user in users:
    print(user.id, user.name, user.email)

# Update
user = session.query(User).filter_by(id=1).first()
if user:
    user.name = "Updated Name"
    session.commit()

# Delete
user = session.query(User).filter_by(id=1).first()
if user:
    session.delete(user)
    session.commit()
